# Audit — 18 September 2026

> **What this is.** An adversarial read of every module in this repository, made on
> 18 September 2026, recording what does **not** hold up. It is a snapshot, not a living
> document: findings stay here as a record even after they are fixed.
>
> **How it was done.** Thirteen independent reviewers, one per certification module plus
> one for the cross-cutting files, each reading every `.md` file in its scope from top to
> bottom before reporting. Criteria were fixed in advance: technical error; a command that
> would not work; an internal contradiction; a claim with no support; a dead reference;
> fabricated output; a hidden failure mode; and exam logistics (which this repository
> forbids). Severity is by **consequence**, not taste:
>
> - **Blocking** — someone who follows it gets a wrong result.
> - **Important** — works today, fails in a foreseeable case.
> - **Minor** — correctable with no functional consequence.
> - **Preference** — not a defect; recorded as opinion.
>
> Reviewers could and did verify against primary sources (project repositories, RFCs,
> FIRST's CVSS specification, vendor documentation) by fetching them. **Every Blocking
> finding was then re-checked here by hand**, and the verdict of that check is recorded
> under each one. A reviewer's report is a claim, not a fact: one finding in this audit was
> refuted on re-check and is recorded as such rather than quietly dropped.
>
> **What this audit is not.** It is a static read. Nobody ran a SIEM, a forensic image, a
> lab range or an exploit against these documents, so nothing here is an empirical claim
> about runtime behaviour. Commands are documented syntax, and the modules say so.

Sections appear in the order the thirteen reviews were confirmed, not in folder order; the
summary table below is the index. Every finding carries the path it lives at.

## eAIS — `04-Emerging-Technologies/eAIS/`

Verdict: **not apt.** Four blocking defects — a regression gate that cannot fail, a sanitiser
that does not remove the channel it claims to remove, a "fail-closed" filter that opens for a
null identity, and an FGSM snippet that cannot run with any input type — sitting on a module
that is otherwise unusually disciplined about stating the limits of its own controls.

1. **[Blocking] The documented regression gate compares the baseline with itself**
   `labs/guardrail-evaluation-lab.md:720` (with `:379`, `:708-710`) —
   `python check_regression.py --baseline baseline.json --current baseline.json`. Both
   tolerances are therefore always satisfied and the gate exits 0 even when the control got
   worse. It is what the same file names at `:709`: "a baseline that follows the current code
   compares the code to itself and always passes".
   Fix: two distinct paths, with the harness writing current metrics to its own file.

2. **[Blocking] "Loader B" deletes the `style` attribute, not the hidden text**
   `labs/injection-lab.md:326` (with `:316`, `:329`, `:339`) —
   `HIDDEN_RE = re.compile(r'style="[^"]*color:\s*#fff+"', re.I)`. The loader presented as
   "sanitising: drop the channels a reader cannot see" removes the attribute and leaves the
   node, so the white-on-white instruction survives in the chunk while `:339` asks the reader
   to list the channels they removed.
   Fix: remove the hidden element, not its style attribute.

3. **[Blocking] `permits` is declared fail-closed and opens when the identity is null**
   `labs/rag-data-leakage-lab.md:230` (with `:116`, `:150`, `:245`) —
   `return chunk.get("tenant") in (tenant, "shared")`. With `{"tenant": null}` the comparison is
   `None in (None, "shared")`, true for every chunk that carries no metadata: an unclassified
   document is served to a null principal, against the lab's own expected observation that it is
   "invisible to *both* tenants".
   Fix: reject a null identity before comparing.

4. **[Blocking] The FGSM fragment mixes numpy and torch APIs and cannot run with either type**
   `methodology/04-adversarial-attacks.md:43-44` (block at `:35-50`) —
   `x = x.astype(np.float32)` followed by `x.requires_grad = True`. `astype` exists only on a
   numpy array; `requires_grad`, `backward()` and `.grad` only on a torch tensor, and torch is
   not imported. Whichever type `x` is, one line raises AttributeError.
   Fix: pick torch and import it, or pick numpy and drop the gradient lines.

5. **[Important] The release gate excludes `bypass_rate` and compares numbers the file calls incomparable**
   `labs/guardrail-evaluation-lab.md:676-681` (with `:699`, `:670`, `:702-704`). The one metric
   the lab says is not self-fulfilling — bypass on unseen variants — is outside the gate, and
   the comparability check ignores `guardrail_version`, `fail_mode` and `runs_per_case`, so a
   switch to fail-open or from N=5 to N=2 is reported as "no regression".
   Fix: include `bypass_rate` with a tolerance and all three fields in the comparison tuple.

6. **[Important] Phase 08's measurement convention cannot represent an error and does not produce the interval it demands**
   `methodology/08-evaluation-and-continuous-red-teaming.md:113` (with `:106`, `:118`, `:128`) —
   `1 if r["outcome"] == "failure" else 0` over a two-value schema, so a timeout, a 429 or a run
   blocked by a control counts as success: a case with 0 failures and 8 errors prints
   "stable-safe" and drags the rate down. It contradicts `02:195` ("a run that failed is not a
   run that was blocked"), and `:128` asks for an interval the code does not compute.
   Fix: separate labels for harness errors and control blocks, outside the denominator, plus the
   upper bound.

7. **[Important] The OWASP mapping uses a superseded edition's numbering and contradicts the rest of the module**
   `methodology/03-model-poisoning.md:17` cites "LLM03/LLM04 (Training Data Poisoning and Model
   DoS families)". In the current list LLM03 is Supply Chain and LLM04 is Data and Model
   Poisoning; the reader who opens the cited URL does not find what the file claims, and another
   file in the same module uses the current numbering.
   Fix: cite by name and edition.

8. **[Important] The declared primary control for a backdoor does not mitigate a backdoor, and the matrix marks it covered**
   `cheatsheets/attack-to-control-mapping.md:32` (with `:138`, `:149`) — "pin version and hash"
   guarantees *which* artifact you load, not that it is benign. The coverage matrix still marks
   that row with a filled dot, so the sheet treats an unmitigated risk as covered.
   Fix: promote the behavioural suite to primary control and lower the mark.

9. **[Important] TM-01a measures generation fluency and scores it as memorisation**
   `cheatsheets/llm-test-case-library.md:164` (with `:225`) — if the sentence was never in
   training it cannot be memorised, so a fluent completion is ordinary generation, not evidence
   of membership; and the failure signature counts "any recoverable fragment" as `leaked`, which
   makes every plausible completion a false leak finding.
   Fix: use real prefixes as canaries and measure overlap against the corpus.

10. **[Important] The module map says one path is not a link when eight are, and all eight exist**
    `tools/observability-and-tracing.md:281-283` (with `:288-291`) — the note claims only
    `methodology/06` was unwritten when the file was created, but the tables leave eight paths in
    backticks, and all eight files are on disk. The same stale note appears in `07:320`, `08:326`
    and `tool-selection.md:184-185`, so the reader following the reading order cannot reach
    phases 06 or 08.
    Fix: make the eight paths links and drop the status note.

## Cross-cutting — root README, `resources/`, `CONTRIBUTING.md`, CI

Verdict: **apt with reservations.** The figures and URLs on the front pages survive checking —
all twelve product pages return 200 with the right titles, the depth table matches the disk

1. **[Blocking] The external sweep declares dead what responds**
   `scripts/utilities/check-links.mjs:106-108` retries with GET only on 405/403/501, so a 404

   `portswigger.net/web-security` → `HEAD=404 GET=200`, and the same for three sibling paths.
   Four healthy links are published as dead every week, and a maintainer who believes it
   "fixes" what works.
   Fix: retry with GET whenever HEAD returns >= 400.
   **Fixed 18 Sep 2026** — the retry is now status-based rather than a fixed list.

2. **[Important] Three version notes disagree with the page that announces them**
   `README.md:87` and `resources/official-links.md:143` (eCTHP "24 July 2025" against a page

3. **[Important] The weekly job can never pass, and that hides the real failures**

4. **[Important] `--external` never sees URLs written as plain text**

   **Fixed 18 Sep 2026.**

5. **[Important] A module with a README and no subfolders is invisible to `check-catalog`**

6. **[Minor] The two landing pages describe CI differently**

10. **[Preference] `certification-map.md` labels itself opinion only at page level**

## eJPT — `01-Fundamentals/eJPT/`

Verdict: **apt with reservations.** Methodology and syntax hold up under checking; the
DVWA lab cannot work as written, and four tool claims are wrong.

1. **[Blocking] The Scenario 3 curl login leaves no authenticated session**
   `labs/practice-scenarios.md:88` — `curl -s -c dvwa.cookies -d "username=admin&password=password&Login=Login"`.
   DVWA's `login.php` validates `checkToken($_REQUEST['user_token'], …)`; without the token it
   answers "CSRF token is incorrect" and redirects, so `dvwa.cookies` carries no session and
   steps 2 and 4 return the login page. The reader concludes the injection does not exist.
   Trigger: a fresh DVWA, first command of the scenario.
   Fix: fetch `login.php` with `-c`, extract `user_token`, send it in the POST.
   *Re-checked here: holds. DVWA 1.9+ enforces the token at every security level.*

2. **[Important] The same scenario would run at level "impossible"**
   `labs/practice-scenarios.md:83` — declares security level *low*.
   The level lives in the `security` cookie; `dvwaPage.inc.php` sets it to `impossible` when
   no cookie arrives, and a curl jar has none, so `exec/` never executes the injection.
   Fix: add `--cookie "security=low"` to the scenario's curl calls.

3. **[Important] `-oJ` does not exist in Nmap**
   `tools/nmap-cheatsheet.md:142` — `| -oJ file | JSON | Programmatic parsing |`.
   Nmap documents only `-oN/-oX/-oS/-oG/-oA`; `-oJ` aborts the invocation, and row 143 is
   wrong too: `-oA` does not produce JSON.
   Fix: delete the row and state that `-oA` = normal/XML/greppable.

4. **[Important] `--proxies` with an `http://` scheme against a SOCKS proxy**
   `methodology/05-pivoting.md:92` — `nmap -sT -Pn --proxies http://127.0.0.1:1080` under a
   comment calling it native SOCKS. The tunnel is created by `ssh -D 1080` (line 88), which
   is SOCKS; Nmap would speak CONNECT at a SOCKS server. Nmap advertises HTTP/SOCKS4 only.
   Fix: `--proxies socks4://127.0.0.1:1080`.

5. **[Important] `cmd.exe` syntax under a "PowerShell" heading**
   `methodology/04-post-exploitation.md:177-178` — `# Windows (PowerShell)` above
   `dir /s /b C:\proof.txt C:\flag.txt 2>nul`. In PowerShell `dir` is `Get-ChildItem`, so
   `/s` and `/b` are treated as paths and error out.
   Fix: `Get-ChildItem -Recurse`, or label the block `cmd.exe`.

6. **[Minor] `-q` is not in OpenBSD `nc`**
   `tools/netcat-essentials.md:119` recommends `-q 1`; the page the same file links (line 216)
   does not document `-q`. Closing after EOF is `-N`.
   Fix: cite `-N`, or attribute `-q` to GNU netcat/ncat.

7. **[Minor] Two different descriptions of the default `-sn` probe**
   `methodology/01-reconnaissance.md:162` says "ICMP echo + TCP SYN to 443/80", contradicting
   `tools/nmap-cheatsheet.md:20-22`. The default set is `-PE -PS443 -PA80 -PP`.
   Fix: align the row.

8. **[Minor] Unsupported claim about Metasploit encoders**
   `tools/metasploit-basics.md:117` — "deprecated and removed most legacy encoders".
   `master` still ships 57 encoders, 24 of them x86, and `shikata_ga_nai.rb` carries no
   deprecation mark.
   Fix: soften to "many are in disuse" and point at `msfvenom -l encoders`.

Also confirmed by the reviewer but beyond the report cap, with evidence: `README.md:66`
dates the eJPT update 31 March 2026 while INE's own page carries a 26 March dateline and a
1 April publication date — and `resources/official-links.md` already states both; three
surrounding errors at `methodology/03-exploitation.md:198` (privileged port),
`labs/practice-scenarios.md:165` (`unshadow` on the wrong host) and
`methodology/02-enumeration.md:190` (SNMP OID described as software + usernames when it
returns process names).

## eCPPT — `02-RedTeam/eCPPT/`

Verdict: **not apt.** The central cracking step of the lab does not crack, and several
operational references are wrong.

1. **[Blocking] `--show` does not crack: Scenario 2 never gets the password**
   `labs/attack-simulations.md:79` (and `:89`) — `hashcat -m 13100 tgs.txt rockyou.txt --show`.
   `--show` only compares the hashfile against the potfile and prints what was already
   recovered; with an empty potfile it prints nothing and cracks nothing. The scenario's
   stated goal ("cracks to `sqlp@ss123`") is unreachable, and the checklist at `:89`
   consolidates the wrong expectation.
   Fix: drop `--show` from the run; use it afterwards to read results back.
   *Re-checked here: holds. `--show` is a read-only query against the potfile.*

2. **[Important] `/krbtgt:` given an LM:NT pair in a mimikatz command**
   `tools/mimikatz-reference.md:67` — `/krbtgt:aad3b435b…:2e2e2e… /ptt`.
   In `kuhl_m_kerberos.c` `/krbtgt` is an alias of `/rc4` and converts a single 16-byte hex
   key; the pair is invalid and the forge fails on key size. Contradicts `ad-commands.md:110`
   and `attack-simulations.md:186`, which use one hash.
   Fix: `/krbtgt:<NT_HASH_32_HEX>`.

3. **[Important] wmiexec does use the ADMIN$ share over SMB**
   `methodology/02-lateral-movement.md:64` and `cheatsheets/ad-commands.md:123` claim no file
   is dropped and no admin share is needed. In `examples/wmiexec.py` the semi-interactive
   shell writes output to the share (`-share`, default `ADMIN$`) and reads it back over SMB.
   If 445/ADMIN$ is filtered — the case where WMI is chosen — no output comes back.
   Fix: state that it needs ADMIN$ over SMB, or `-nooutput`.

4. **[Important] `--ldapuser` / `--ldappass` do not exist in SharpHound**
   `tools/bloodhound-guide.md:91`. The real options are `--ldapusername` and
   `--ldappassword` (`src/Options.cs`, 2.X branch); the parser rejects the unknown option and
   collection never runs.
   Fix: use the correct spellings.

5. **[Important] WS01 does not have the IP Scenario 4 uses**
   `labs/attack-simulations.md:142` connects to `10.0.0.20`, but `labs/ad-lab-setup.md:18`
   and `:70` put WS01 on a DHCP scope of `10.0.0.100-200`.
   Fix: use the real address, or fix it in the lab guide.

6. **[Important] `grep` inside a Windows shell**
   `labs/attack-simulations.md:117` (and `:156`) — `whoami /groups | grep -i "Domain Admins"`
   inside an `evil-winrm` session, which is PowerShell on Windows and has no `grep`.
   Fix: `Select-String`.

7. **[Minor] The LDAP attribute-case claim is backwards**
   `cheatsheets/ad-commands.md:144` — "LDAP filters are case-sensitive for attribute names".
   Attribute descriptions are case-insensitive (RFC 4512) and AD complies.
   Fix: delete the claim.

8. **[Minor] A CVSS comment that contradicts its own vector**
   `methodology/05-reporting.md:64-65` — "(no privileges)" over a vector containing `PR:L`.
   Fix: say "low privileges (PR:L)".

## eMAPT — `02-RedTeam/eMAPT/`

Verdict: **apt with reservations.** Most of the module survives checking, but two blocking
defects leave published drills that cannot be run.

1. **[Blocking] The iOS path of UnCrackable uses a bundle and an id that do not exist**
   `labs/setup-guide.md:112-113` (repeated in `labs/practice-exercises.md:161-163`) —
   `xcrun simctl install booted UnCrackable-Level1.app` and `xcrun simctl launch booted owasp.mstg.uncrackable1`.
   The IPA MASTG publishes contains `Payload/UnCrackable Level 1.app` with
   `CFBundleIdentifier = sg.vp.UnCrackable1` and `DTPlatformName = iphoneos`;
   `owasp.mstg.uncrackable1` is the Android package of the same crackme. The install fails on
   the missing bundle, the launch fails on an unknown id, and a device build does not install
   into the simulator anyway.
   Fix: use the real bundle id with a simulator build, or point at the jailbroken-device route.

2. **[Blocking] `--no-pause` does not exist and its comment says the opposite**
   `tools/android-tools.md:158-159` (also `cheatsheets/mobile-commands.md:76`,
   `tools/burp-setup.md:143`, `labs/practice-exercises.md:64`) — "Spawn, keep the app paused,
   then resume" over `frida -U -f com.example.app -l hook.js --no-pause`. Current frida-tools
   defines only `-P/--pause` ("leave main thread paused after spawning program"), so the
   argument is rejected and the command never starts; where it did exist (≤ 10.0.0) its meaning
   was "start the main thread automatically", i.e. it never paused. The early hook the text
   demands does not happen.
   Fix: drop the flag, and use `-P` when a paused spawn is wanted.

3. **[Important] `android heap search strings` is not an objection command**
   `methodology/03-dynamic-analysis.md:90` — the `android heap search` group has only
   `instances`; the reader gets the help text instead of a memory search. The real one is
   `memory search "<pattern>" --string`.
   Fix: use `memory search … --string`.

4. **[Important] jadx paths that do not exist: `jadx-out/assets` and `jadx-out/res`**
   `methodology/02-static-analysis.md:133` — jadx writes `out/sources` and `out/resources`;
   `res/`, `assets/` and the manifest live under `resources/`. The grep fails with "No such
   file or directory", so the secret sweep over the very folder the step says hides them
   returns a false negative.
   Fix: search `jadx-out/resources/`.

5. **[Important] `adb backup` presented without the Android 12 restriction**
   `methodology/05-exploitation.md:37-38`. Since Android 12 the data of apps with
   targetSdk ≥ 31 is excluded from `adb backup` unless the app is debuggable; the backup comes
   out empty and the reader concludes nothing is stored. `labs/practice-exercises.md:133`
   already scopes the case ("older Android image"), so the module contradicts itself.
   Fix: require targetSdk < 31 or `debuggable=true`, as the lab already does.

## eIAMA — `04-Emerging-Technologies/eIAMA/`

Verdict: **not apt.** The lab teaches accepting ID-token claims without verifying them, and
the protocol cheatsheet merges two different Kerberos attacks.

1. **[Blocking, with a qualification] The lab authorises from decoded claims that are never verified**
   `labs/iam-scenarios.md:112-115` — `id_token.split(".")[1]` is base64-decoded and stored as
   `session["claims"]` with no signature, `iss`, `aud` or `exp` check, while the module

   `methodology/05-federation.md:97`) without flagging the example as deliberately unsafe.
   Qualification from the re-check: the token here comes from the back-channel token response
   (`:108-112`), not from the browser, which narrows the attack surface compared with trusting
   a token handed in by the client — but the missing verification is still a defect in a
   pattern students copy, and without `nonce`/`iss`/`aud` there is no defence if the source of
   the token changes.

   PyJWT and JWKS.
   *Re-checked here: holds, with the nuance above.*

   `labs/iam-scenarios.md:95,99` — only `state` is generated. OIDC Core 3.1.3.7 requires the
   `nonce` claim to be checked *if* a nonce was sent; none is sent, so none is compared, while

   it (`cheatsheets:208`).

## What to do with this list

The findings split into three buckets, and only the first two are mechanical.

**Already fixed while writing this audit** (all in tooling added the same day, so the fix is part
of this commit): the external sweep's HEAD/GET false positives, the permanently-red weekly job
caused by lab-local URLs, the blind spot for bare URLs, the module-without-subfolders hole in
`check-catalog`, the GitHub-incompatible anchor slugs, and link syntax inside inline code being
read as a link.

**Mechanical, one or two lines each, no editorial judgement required** — around seventy
findings. They are wrong flags (`nmap -oJ`, `--proxies http://` for a SOCKS proxy, `--ldapuser`,
`lynis show warnings`, `oscap xccdf generate tailoring-file`, `frida --no-pause`,
`client collect`, KAPE `!EZ1`, `vol windows.memdump`, `ils -m /mount`, `windows.yarascan`), wrong
field or column names (`New_Process_Name`, `name/enabled/last_logon` in osquery,

the LDAP attribute-case claim), missing arguments (`--dump` in sqlmap, `-b` in the
session-fixation probe, a CSRF token in the DVWA login), wrong arithmetic (`Content-Length: 4`
over a 29-byte body, a CVSS vector that scores 8.6 while claiming 7.5), a false `Z` on a local
timestamp, files promised and never written, and dead links
(`activecountermeasures/rita`, `EricZimmerman/KAPE`, the seven external 404s, and the stale
`nist-ai-600-1` URL repeated across nineteen eAIS files).

judgements against primary sources and upstream source code, not observations — strong enough to
act on for a wrong flag, and worth a verification run before rewriting anything whose behaviour
